# Model Card：AI Network Intrusion Detection

一頁式摘要：這個模型能做什麼、不能做什麼、在什麼條件下可以信任它的輸出。數字出處見 [`progress_log.md`](progress_log.md)、[`interview_talking_points.md`](interview_talking_points.md)、[`results/leave_one_attack_out/report.md`](../results/leave_one_attack_out/report.md)。

## 這個模型是什麼

- **任務**：輸入一筆網路流量的 80 個數值特徵，輸出（1）是否為攻擊、（2）攻擊類型（15 類，含 `BENIGN`）、（3）該次判斷的信心分數。
- **演算法**：Random Forest（100 棵樹，`class_weight="balanced"`）。曾與 Logistic Regression 比較，Random Forest 全面較優。
- **訓練資料**：CIC-IDS2017 官方 `MachineLearningCSV`，8 個檔案、5 個工作日、310 萬筆流量、清理後約 283 萬筆。
- **產出介面**：`api/main.py`（FastAPI）+ `web/index.html`（離線重播儀表板）。

## 資料集限制

- CIC-IDS2017 是 2017 年在實驗室環境擷取的資料，攻擊工具、網路設備與正常流量樣態都不代表現在的真實網路環境。模型可能學到的是「這份資料集裡各攻擊類型的特徵」，不是網路攻擊的通用規律。
- 每種攻擊只在單一天出現過（例如 `Bot`/`PortScan`/`DDoS` 只在星期五），日期與攻擊類型高度糾纏，無法用這份資料單獨切出「純日期效應」。
- **模型只在 CIC-IDS2017 上驗證過，不能宣稱能偵測所有真實世界的網路攻擊。** 若要對外部流量宣稱有效，需要用其他資料集（如 CSE-CIC-IDS2018、UNSW-NB15）做獨立測試，本專案尚未做這一步。

## 各驗證分數可以信任到什麼程度

| 驗證方式 | 說明 | 二元 Recall | 多類別 Macro F1 | ECE（校準誤差） |
|---|---|---:|---:|---:|
| 隨機切分 | 相似流量可能同時落入訓練/測試集，容易高估 | 99.86% | 94.05% | 0.05% |
| 依類別時間切分 | 每類各自依時間排序，保留最新一段當測試 | — | 74.01% | 1.13% |
| 按日期切分（一至四訓練、五測試） | 同時混合「日期變化」與「未見攻擊類型」 | **7.93%** | — | **32.97%** |
| 留一攻擊類型（11 類個別測試） | 完全排除單一攻擊類型於訓練外 | 平均 **58.34%**（依攻擊而定，見下） | — | 未計算 |

**唯一可以拿來宣稱「模型很準」的是隨機切分／類別內時間切分的分數，而且要註明前提。按日期切分與留一攻擊的分數，代表的是模型目前做不到的事，不是額外的負面評語，是誠實的能力邊界。**

信心分數同理：隨機切分下信心分數確實有校準（ECE < 0.1%）；但按日期切分時，88% 的預測都宣稱 99.7% 信心，實際只對 66.8%——**信心分數的可信度會隨資料分布改變而失效，不能假設訓練時測出的校準品質可以帶到新環境**。

## 各攻擊類型的樣本量與可靠度

| 攻擊類型 | 樣本數 | 評估建議 |
|---|---:|---|
| `BENIGN`、`DoS Hulk`、`PortScan`、`DDoS` | 12.8 萬～227 萬 | 樣本充足，百分比可信 |
| `DoS GoldenEye`、`FTP-Patator`、`SSH-Patator`、`DoS slowloris`、`DoS Slowhttptest` | 5,000～10,000 | 樣本尚可，百分比大致可信 |
| `Bot`、`Web Attack Brute Force`、`Web Attack XSS` | 300～2,000 | 樣本偏少，百分比僅供參考 |
| `Heartbleed`（11）、`Web Attack Sql Injection`（21）、`Infiltration`（36） | 個位數～數十筆 | **樣本嚴重不足，任何百分比（含 100%）都不具統計意義，不納入主要結論** |

## 面對「從沒訓練過的攻擊」會發生什麼事（留一攻擊實驗）

模型是**封閉式分類器**：無論輸入多異常，都必須從已知的 15 個類別裡選一個答案，沒有「未知／需要人工複查」的輸出。實測結果（詳見 `results/leave_one_attack_out/report.md`）：

- `Bot`、`PortScan` 完全移出訓練後，二元 Recall 分別從 99%+ 掉到 **0%** 與 **0.34%**，而且幾乎全部是「信心 ≥80% 仍判為正常」的高信心漏報。
- 少數攻擊家族之間有部分可轉移性（例如 `DoS slowloris` 未見時 Recall 仍有 97.73%），但不能一概而論。
- **這代表系統目前無法可靠偵測任何訓練資料裡沒有的全新攻擊手法，而且遇到這種情況時，系統本身通常不會發出任何警訊。**

## 什麼情況需要人工複查（現況，非最終方案）

- API 目前用「信心 < 80%」標記 `low_confidence`，這只是**展示用的複查門檻，不是通過驗證的部署安全保證**——按日期切分的實驗已經證明，80% 以上的信心在新資料分布下仍可能大量錯誤。
- 目前沒有任何機制能標記「這筆流量長得不像任何訓練過的類別」（開放集偵測／異常偵測），這是最大的已知缺口。
- 實務上應該對「模型判定為 BENIGN、但信心明顯低於該模型在驗證集上的平均信心」的流量提高警覺，而不是只用單一固定門檻。

## 目前不具備的能力（誠實列出）

- 沒有身分驗證、速率限制、模型版本管理、預測紀錄持久化、資料漂移監控。
- 沒有即時封包擷取與 Flow 特徵產生管線；儀表板重播的是預先算好的 97 筆離線樣本，不是即時流量。CICFlowMeter 的許多特徵本身要等一個 flow 結束才能計算，即使接上即時流量也不會是封包抵達當下就能判斷。
- 儀表板展示樣本是**刻意平衡挑選**（每類別各取幾筆正確／錯誤案例），畫面上的攻擊比例、漏報比例只描述這批展示樣本，不代表真實網路或完整測試集的比例。

## 建議的下一步（依優先順序）

1. 針對「日期變化」與「全新攻擊類型」分別做更乾淨的量化（留一攻擊實驗已完成後者的一部分）
2. 補齊所有攻擊類型的樣本數與 per-class recall，而不是只看整體指標
3. 探索異常偵測／開放集分類，讓系統至少能對「不像任何已知類別」的流量發出警訊
4. 若要對外宣稱通用性，用第二個獨立資料集做外部驗證
5. 這些做完之後，才是討論即時管線、身分驗證、速率限制等產品化工程的時機
